# 自学习流程协议 v1.1 —— RSI 三通道（2026-10-10 新增）

> **目的**：把框架的「自我改进」从隐式习惯升级为**显式协议**（用户 2026-10-09 要求"优化自学习
> 框架自学习的流程本身"）。借鉴 Recursive Self-Improvement（RSI）研究的分类法：
> **语言演化**（Reflexion）/ **过程演化**（Voyager）/ **结构演化**（AlphaEvolve）。
> **元更新规则**（综述 §式 5）：`S_{k+1} ← U(S_k, τ_k, F_k)` —— S = 可演化状态
> （文档/脚本/协议），τ = 本轮轨迹，F = 环境反馈（实验结果、用户反馈、事故）。

---

## 一、三通道定义（本框架的具体对应）

### 通道 A · 语言演化（Reflexion 式：失败 → 语言线索 → 改变未来推理）
- **S =** `references/precedent.md`（先例案卷 P-01~P-38）+ 判决书 reason_bucket
- **触发**：任何 reject/invalid/pending-with-surprise 的轮次
- **动作**：把失败合成**固定三元组**写入先例案卷：
  `P-xx = {trigger: 什么信号触发了错误结论, mechanism: 为什么错（机制层）, rule: 从此以后的一条可检查规则}`
- **验收**：新三元组必须能被**至少一个现有判据**（G/F/D/M）机械检查——
  写不进判据的教训 = 没消化。
- **本周实例**：P「成本重复扣除险致假阴性」（10-08）→ 已固化为 M 系列与 F 组的隐含检查。

### 通道 B · 过程演化（Voyager 式：成功 → 可复用技能 → 技能库）
- **S =** `scripts/` 目录（每个脚本 = 一个技能）+ SKILL.md §八 目录（= 技能注册表）
- **触发**：同一分析动作被**手工执行 ≥2 次** ⇒ 必须固化为脚本（Voyager"合成技能"判据）
- **动作**：写脚本 → 带 `--selftest` → 注册 SKILL.md 目录（含调用签名）→ 从此作为原子技能被组合
- **技能库现状**（本周期新增）：
  | 技能 | 功能 | 触发来源 |
  |---|---|---|
  | `masters_checklist.py` | M-1~M-12 软检查 | 10-10 大师学习 |
  | （待补）簇口径统计器 | 自相关聚集的诚实 n | 10-08/09 两轮 pending 的共同缺口 |
  | （待补）decay_tracker | adopt 结论的前向衰减跟踪 | M-6 |
- **验收**：新脚本必须通过自身 `--selftest` 且不破坏 `selftest_all.py`。

### 通道 C · 结构演化（AlphaEvolve 式：框架代码自身 = 假设空间）
- **S =** SKILL.md 的协议文本 + 判据定义 + 主引擎脚本
- **触发**：三方向任一出现**系统性缺口**（跨 ≥2 轮重复出现同类问题）⇒ 允许改协议本身
- **动作**：LLM 作为变异算子，对协议/判据/脚本提出**最小突变**；每个突变必须：
  ① 声明动机（对应哪位大师/哪次事故）② 通过全量自检 ③ 保留旧版备份（`*.bak-*`）
- **验收**：突变后 `selftest_all.py` 全绿 + 本次实验能证明新结构 ≥ 旧结构（不能证明则回滚）
- **本轮实例**：M 系列注入（12 条规则 + 检查器 = 结构演化的一次成功突变，10-10）。

### 通道 D · 外部演化（模仿世界 —— ★ 永不自满元规则，2026-10-10 用户指令沉淀）
- **元规则**：本框架**永远不是最优的**。外部永远存在值得借鉴的技能、框架、论文与实战复盘。
- **触发**（三选一必做）：① 收敛四闸触发（内部搜索枯竭）⇒ **必须**转向外部搜索，禁止硬开内轮
  ② 每月例行一次（日历驱动）③ 用户要求时。
- **动作**：
  1. WebSearch 同类优秀技能/框架/论文（关键词族：self-improving agent、quant research
     framework、Reflexion/Voyager/AlphaEvolve 后继、竞品 skill hub、大师新分享）
  2. 对每个外部候选问三问：**有我们没有的机制吗？能否翻译成可检查规则（M/G/F 格式）？
     能否固化为脚本（B 通道技能，须带 --selftest）？**
  3. 翻译入库：叙事性经验 → M 系列规则；可执行能力 → scripts/ 技能 + 注册 SKILL.md
  4. 重打分发包 + 在本文件变更日志登记（日期/来源/吸收了什么/变成了什么）
- **验收（硬性）**：借鉴必须"翻译成可执行检查或脚本"才能入库；**纯叙事不收**。
- **首例**：2026-10-10 M-1~M-12（Simons/Thorp/de Prado/国内头部）+ RSI 三通道协议本身。

## 二、元学习环的运转规程（谁在什么时候做什么）

| 时点 | 动作 | 通道 |
|---|---|---|
| 每轮 round 提交前 | `masters_checklist --round` 自查 M 缺口 | B |
| 每轮 verdict 后 | 裁判检查 M-6（adopt⇒decay_tracker）/ M-12（采纳⇒联合评估） | B |
| 每次 reject/invalid | 失败合成三元组入 precedent.md（语言演化） | A |
| 同类问题 ≥2 次 | 允许结构演化突变（改协议/判据/脚本） | C |
| 每次 adopt | 登记 decay_tracker（前向衰减监控） | M-6 |
| 每月 | 技能库盘点：手工重复 ≥2 次的分析动作固化为脚本（Voyager 课程） | B |

## 三、RSI 成功三条件对照（何时该信任自我改进）

| 条件 | 本框架 | 状态 |
|---|---|---|
| **可验证结果**（verifier 存在） | 回测/事件研究/噪声带/F6/自检 40+25+10+13 项 | ✅ |
| **密集探索**（尝试便宜） | 数据驱动研究，一次实验分钟级 | ✅ |
| **可组合** | 脚本=原子技能，研究脚本可 import 互组合 | ✅ |
| （反例警示）| 主观叙事类判断**不可验证** ⇒ 不进入自学习环（如"大师经验"本身只能转成可检查规则） | ⚠️ 明确 |

**RSI 边界（诚实）**：de Prado 的 FST 说明——试验次数够多，纯噪声也能造出任意好看的回测。
**自改进环自身也受同一规律约束**：每轮结构突变都是一次"试验"，M/checklist 的每次扩充都在
增加框架的试验次数 ⇒ **框架自身的 DSR 也应定期复核**（防止"为规则而规则"的规则通胀）。
⇒ 新增纪律：**结构突变（通道 C）每季度复盘一次**，删掉从未被触发过的规则/检查。
