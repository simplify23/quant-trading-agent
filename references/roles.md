# references/roles.md —— 三角色职责（v2.0）

> v2.0 的原则：**每个角色的产出物都被引擎校验**。写不清楚 = 本轮作废，不靠自觉。

## 一、正方（探索者 / 代码优化实现者）

**基础职责**：主张采纳或延续；每条主张挂实验/先例 ID；主动声明失效条件。

**v2.0 硬契约**

1. **回填 `responded_tasks`**：上一轮 `next_round.proponent_tasks` 里 `blocking=true` 的任务，
   本轮必须在 `proponent.responded_tasks` 里列出已完成的 ID。**没回填 = 没响应**，引擎按轮累加 `nag_level`。
2. **每轮交付代码级优化点 `code_opt_points`**（BS-x）：扫「**写死在代码里、从未进过搜索自由度**」的地方 ——
   权重只有两档 / 开关只有开与关 / 候选集写死 topN / 再平衡日历写死自然月 / 参数是常量字面量。
   每条含 `id / locus（文件:函数）/ why_hardcoded`。
   **机制**：调参是在**旧自由度里再抽样**；放开新自由度才是扩搜索空间（先例 P-12）。
3. **执行裁判派工**：`next_round.proponent_tasks` 是本轮工作清单，台账可查「这轮做了什么、响应了哪条」。
4. **边界自报**：候选声明 `uses`（依赖变量）、`family`（同族计数用）、`failure_conditions`。

**举证要求**：主张 → 实验 ID；数字 → **自己跑出来的机读指标**，不允许转述别人的回测。

## 二、反方（政委：既守风险，又开药方）

**基础职责**：针对性质疑；每条反对挂**预注册预期**（「若是真效应，应看到 X；若只看到 Y ⇒ 判假」）；
命中先例驳回区的提案不予受理。**「我觉得不行」不受理。**

**v2.0 硬契约 —— 政委包 `adversary.commissar_pack`**

```
commissar_pack:
  risk_register[]        # 防守：这个候选可能怎么害人
    - risk            风险点（一句话）
    - trigger         触发条件（可观测的读数，如「单年占比 > 50%」）
    - action          处置动作（回退 / 降级 / 加闸）
    - severity        high | medium | low
  opt_prescriptions[]    # 进攻：怎么改会更好（★ 这条是关键，缺 ⇒ invalid）
    - target          改哪里，写明「文件:函数」或模块，禁止写「优化一下模型」
    - action          可执行动作（能被另一个人照着做出来）
    - mechanism       为什么应该有效（要可被检验）
    - expected_delta  事前预期读数（如「Calmar ≥ 基线 + 0.15」）
    - cost            low | medium | high（时间/改动面/数据依赖）
    - priority        1 最优先
    - rollback        回退口径（改回什么、删掉什么）
```

**为什么把反方叫「政委」**：只否决不建设，等于把反对能量泄掉；政委的职责是**把反对转成下一轮的搜索方向** ——
反方最清楚哪个格子还没被击穿。因此非采纳轮**没有处方就是失职**（P6，本轮直接 invalid）。

**接棒质疑**：裁判在判决书里指定 `adversary_focus`（正方本轮未被反驳的主张），下一轮优先击穿它们。

## 三、中立裁判（取证 + 裁决 + 派工 + 催办）

**基础职责**：独立取证（自己跑实验，二手数据 = 传声筒）→ G1–G9 / F0–F6 逐条裁定 → 三态判决 → 归档先例。

**v2.0 硬契约**

1. **派发下一轮指令**：判决书必须含 `next_round`，其中 `proponent_tasks` 至少包含
   ★**一条 `kind=code_optimization`**（持续推进正方的代码优化工作，**这是裁判的固定动作，不是可选项**）。
2. ★**催办（coach）**：把「派工」升级为「盯办」——
   ```
   coach:
     nag_level          0=已响应 / 1=点名催办 / 2=停工清偿 / 3=终止迭代
     nag_message        写给人看的催办语（点名欠账任务 ID + 明确要求）
     must_do[]          本轮必须清偿/推进的任务（含 code_optimization）
     code_backlog_open  正方累计交付的 BS-x 数量（= 已有多少新自由度在排队）
     escalation         null | "hold_new_candidates"
   ```
   **nag 的算法**：上一轮派了工、而本轮 `responded_tasks` 未覆盖其中 `blocking=true` 的任务 ⇒ nag+1；
   全部响应 ⇒ 归零。**nag ≥ 2 ⇒ `hold_new_candidates=true`（停工清偿）**；**nag ≥ 3 ⇒ 收敛停止**。
3. ★**部署审计（D0–D4）**：当轮次声明了 `deploy.target`（上线/实盘/影子盘），裁判必须
   **自己重算被审代码的 sha256** 再与审计报告比对（防「审完又改」），并检查
   报告存在 / 无 P0 / 有回滚点 / 报告未过期。**任一不过 ⇒ 不允许接真实资金或影子账本**，
   把 `adopt` 降级为 `pending/deploy_blocked` 并派 `preflight_fix` 任务。
   ⇒ 审计工具的自检、规则表与人工清单见 `references/preflight-audit.md`。
4. **收敛判定**：维护 `rounds_since_adopt` / `budget_left` / nag，四闸任一触发即宣布收敛并写明 `stop_reason`。
   收敛后继续硬开轮次 = 多重检验空转。
5. **跨轮学习**：同族候选 ≥2 次被驳 ⇒ 把下一轮锁定为「机制证伪实验」，禁止调参重测。
6. **白噪声自检**：`--selftest` 必跑 —— 裁判在纯噪声上不得给出 adopt；DSR 必须识破「40 次试错挑最优」。

## 四、角色与执行者的对应（谁演谁）

| 角色 | 可以是谁 | 不允许 |
|---|---|---|
| 正方 | 你 / 一个探索型 agent / 一个调参脚本 | 自己给自己发证据、转述别人的回测 |
| 反方 | 另一个 agent / `adv.py` 这类反对者脚本 / 你自己扮演 | 只写「有风险」不给处方；处方不给回退口径 |
| 裁判 | 独立跑数的那一方（可与正方同一执行者，但**必须重跑**） | 采信转述数字；跳过 F 组体检直接给 adopt |

★ **同一个执行者可以身兼两角，但「裁判取证」这一步必须是重新跑一遍**，不能把正方贴过来的数抄进判决书。
